# 위험도 예측 한눈에 보기 — 발표·보고서용

> 작성 최현영 · 11/27. 예측 파트(학습 장성은 / 서빙·검증 최현영)를 **발표 한 장·보고서 한 절**로 옮길 수 있게 모은 요약.
> 숫자는 모두 아래 출처 문서에서 가져왔고, 출처가 바뀌면 이 문서를 고침. 규칙의 기준은 [api.md](api.md) 5장.

## 한 줄 요약
**설문 9문항만으로 당뇨·고혈압 "전단계 이상" 위험을 0~100점으로 보여 주는 로지스틱 모델.**
단순 기준(나이만·나이+BMI)보다 확실히 낫고, XGBoost와 성능 차이가 없어서 **설명할 수 있는 쪽**을 골랐다.

## 1. 풀려는 문제
- 30~60대 사용자가 **병원 검사 없이 설문만으로** "내 위험이 어느 정도인지, 무엇을 바꾸면 좋아지는지" 알게 하기
- 멘토링 피드백(11/17): 모델 코드는 AI가 짜 준다 → 핵심은 **"이 모델이 왜 좋은지 증명"** (REQ-NFR-014)

## 2. 데이터와 모델
| 항목 | 내용 |
|---|---|
| 데이터 | 국민건강영양조사 2022~2024, 30~69세, 해당 질환 진단자·임신부 제외 (원본은 레포 밖, 집계만 공유) |
| 정답 | 검진 수치 기준 **전단계 이상** — 당뇨: 공복혈당 100↑ 또는 당화혈색소 5.7↑ / 고혈압: 130/80↑ |
| 인원 | 당뇨 9,256명 (위험 41.7%) · 고혈압 8,242명 (위험 31.2%) |
| 입력 | 설문으로 답할 수 있는 것만 9개: 성별·나이·BMI·그 질환 가족력 3개·음주 횟수·음주량·흡연 (v2, #150) |
| 모델 | 표준화 + 로지스틱 회귀 (계수 JSON으로 서빙), MLflow에 파라미터·데이터 sha256·지표 기록 |
| 평가 | 층화 80/20 분할(시드 42), 평가 세트 부트스트랩 1,000번으로 95% 신뢰구간 |

## 3. "왜 좋은가" 증명 4가지 ([model-comparison.md](model-comparison.md))
| 질문 | 답 | 근거 |
|---|---|---|
| 단순 기준보다 나은가? | **예** | AUROC 차이 신뢰구간이 0 아래. 고혈압은 나이만보다 +0.153, 나이+BMI보다 +0.055 |
| 복잡한 모델이 더 낫지 않나? | **차이 없음** | XGBoost − 로지스틱: 당뇨 −0.001, 고혈압 −0.008 (신뢰구간이 0을 걸침) → 계수로 요인·건강 나이를 설명할 수 있는 로지스틱 유지 |
| 위험 단계가 실제로 갈리나? | **예** | 낮음 → 주의 → 높음 실제 위험 비율: 당뇨 15% → 47% → 68%, 고혈압 18% → 43% → 63% |
| 점수를 믿어도 되나? | **집단 평균으로는 예** | 보정 곡선이 대각선 근처, 보정 기울기 1.06·1.07 → "34점 근처인 사람들 중 약 34%" |

| 모델 | 당뇨 AUROC | 고혈압 AUROC |
|---|---|---|
| **로지스틱 (서버)** | **0.743** | **0.722** |
| 나이만 | 0.667 | 0.569 |
| 나이+BMI | 0.732 | 0.667 |
| XGBoost | 0.743 | 0.714 |

- 성별 안에서 구분하는 힘은 0.68~0.76 (전체 AUROC엔 성별 차이도 섞여 있어서 따로 봄)
- 그림 3장: [ROC](images/model-comparison/roc.png) · [위험 단계별 실제 비율](images/model-comparison/levels.png) · [보정 곡선](images/model-comparison/calibration.png)

## 4. 서비스로 옮기면서 지킨 것 ([prediction-pipeline.md](prediction-pipeline.md))
| 원칙 | 어떻게 | 요구사항 |
|---|---|---|
| 학습 = 서빙 | 설문 → 입력 변환 함수 하나(`features.py`)를 학습·서빙이 같이 씀. 점수 반올림·30/60 단계도 학습 평가와 같은 함수 | REQ-NFR-017 |
| 같은 입력 = 같은 결과 | 실제 모델 JSON으로 같은 입력 100번 → 점수·단계·요인 같음 (`test_consistency.py`) | REQ-NFR-017 |
| 설명 | 요인은 "+5살"처럼 나이로: 같은 성별 평균과 비교한 7문항 산식, 0살 빼고 큰 순 3개. 건강 나이는 10살 단위 | REQ-PRED-002 |
| 빠르게 | 담당 API 12개 P95 13ms 이하 (기준 3초). 예측은 워커 없이 FastAPI에서 바로 | REQ-NFR-016 (#156) |
| 버전이 바뀌어도 | 점수마다 `model_version` 저장, 예전 버전 행은 보관한 그 버전 JSON으로 설명 (v1 → v2 배포 때 기존 사용자 건강 나이 유지) | #160 |
| 안전한 표현 | "위험도 참고값", "의료 진단이 아니며 전문가 상담 필요". 기록만으로 "위험이 줄었다"고 하지 않고 재계산 점수가 실제로 내려갔을 때만 | REQ-NFR-001·003 |

## 5. 쓰면서 좋아지게 ([feedback-loop.md](feedback-loop.md))
```
선택 동의(MODEL_IMPROVEMENT) → 검진 1건마다 앞뒤 30일 안 가장 가까운 설문과 짝
→ (입력, 정답) 쌍 CSV (순번만) → 국건영 + 사용자 쌍으로 재학습 → 같은 평가 세트에서 나을 때만 v3
```
- 새 테이블 없이 뽑는 순간 동의를 확인 → 철회하면 다음 재학습부터 자동으로 빠짐
- 정답 0은 두 수치가 다 있고 다 정상일 때만 (하나만 보고 0을 주면 13.7%가 틀림, 국건영 집계)
- 구현: `scripts/export_feedback.py` (#162), 동의 화면 (#163), 재학습·비교 (성은)
- 데모데이는 가상 데이터로 흐름만 보여 줌 (REQ-NFR-018 비고)

## 6. 한계 (발표 Q&A 대비)
- **외부 검증 없음**: 평가 세트 하나(20%)의 부트스트랩이라 다른 연도·다른 데이터에서는 확인 안 함
- **설문만 쓰는 모델의 상한**: 검진 수치를 쓰는 모델보다 AUROC가 낮은 건 예상된 범위 → 그래서 검진 수치가 있으면 기준표 판정을 따로 보여 줌 (5-1)
- **"낮음"도 위험 0이 아님**: 낮음의 실제 위험 15%·18% → 화면의 낮음은 "상대적으로 낮다"는 뜻
- **점수가 높게 보이는 이유**: 정답이 "전단계 이상"이라 위험 비율 자체가 높음 (보정은 맞음)
- XGBoost는 튜닝 안 함 (튜닝해도 지금 차이로는 설명 가능성을 포기할 이유가 없음)

## 7. 발표 30초 스크립트
> "저희 위험도는 국민건강영양조사 1만 명 가까운 데이터로 학습한 로지스틱 모델이에요.
> 설문 9문항만 쓰는데도 나이·BMI만 보는 기준보다 확실히 잘 구분하고, XGBoost와는 차이가 없었어요.
> 그래서 '체중 때문에 +6살'처럼 이유를 설명할 수 있는 모델을 골랐습니다.
> 위험이 '높음'으로 나온 분들은 실제로 3명 중 2명꼴로 전단계 이상이었고,
> 동의한 사용자의 검진 수치로 다시 학습해서, 더 나을 때만 새 버전으로 올리는 구조까지 만들었습니다."
