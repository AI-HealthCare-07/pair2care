# 참여기업(Talos) 주제 안내 원문 정리

> 요구사항 정의서 작성 시 기준 문서. 필수 3개는 빠짐없이 `REQ`로 옮김.

## 주제
만성질환(고혈압·당뇨 등) 생활습관 챌린지 웹 서비스

## 선정 배경
공공 의료 데이터로 AI 모델 개발·서비스화 경험. 모델 학습부터 배포까지 실무 환경과 유사하게 구현. 질병 예측, 건강 모니터링, 의료 상담 AI 챗봇 등 실질적 문제 해결이 목표.

## 필수 기능
1. **만성질환 예측 모델링**
   - Kaggle, AIHub, HuggingFace 등 공개 데이터셋·모델 활용
   - 사용자 건강 데이터 기반 예측 모델 구축
   - 만성질환 발병 가능성 예측
2. **만성질환 추적 대시보드**
   - 사용자 활동·건강 데이터(직접 입력 또는 행동 기반 설문) 시각화
   - 예측 모델 기반 발병 가능성 변화 추이 제공
   - 그래프·차트로 직관적 제공
3. **생활습관 챌린지**
   - 자유 구현 (예: 걸음 수, 물 섭취, 운동 챌린지)

## 선택 기능
1. **LLM 기반 예방 행동 추천**: 건강·행동 데이터 기반 프롬프팅, 맞춤형 행동 가이드, 일일 단위 추천
2. **이미지 분류 기반 식단 분석**: 식단 사진 → 음식 분류, 개인별 영양소 분석, 부족 영양소·개선 피드백
3. **알림 기능**: 건강·행동 데이터 입력 알림, 챌린지 참여·체크 알림, 주요 가이드 확인 알림

## 평가 기준 (참여기업 안내 3장, 11/20 추가)
> 공개는 종합 점수·순위만, 항목별 점수는 비공개, 팀별 피드백 별도. 세부 항목마다 0~5점  
> 5점 공통 기준: 요구사항 완전 충족 + **정량적 근거·문서·테스트 결과**가 명확함  
> 평가 시점: 종료일 1주일 전까지 배포 완료 (12/30 종료 → **12/23까지 배포**)

| 번호 | 평가 항목 | 5점 기준 (요약) |
|---|---|---|
| 1-1 | 문제 정의로 서비스 필요성 분석 | 대상·발생 상황·영향 범위를 수치·사례·시장 데이터로 제시 |
| 1-2 | 요구사항 분석 | 기능/비기능 구분 + 우선순위 명확 |
| 1-3 | 기획 문서 양식·구체성 | 양식 준수 + 화면 흐름도·기능 정의·데이터 흐름 모두 포함 |
| 2-1 | 기술 스택 | 선택 이유 + 대안 비교 제시 |
| 2-2 | 확장성 | 기능 확장을 고려한 모듈 구조·인터페이스 분리 |
| 2-3 | 아키텍처 | 계층 구조 명확, 의존성 분리 |
| 3-1 | 모델 성능 검증 | 학습·검증 분리 + 지표 2개 이상 + 실험 비교 결과 |
| 3-2 | 비동기로 학습·추론 성능 개선 | 비동기 적용 + 개선 결과 **수치** |
| 3-3 | 동일 입력 결과 편차 최소화 | 같은 입력 반복 테스트로 일관성 검증 |
| 3-4 | 사용자 피드백 반영 | 피드백 수집 → 저장 → 개선·재학습 구조까지 구현 |
| 4-1 | 화면 흐름 | 주요 기능 3~5단계 이내 접근, 직관적 흐름 |
| 4-2 | 일관된 사용 경험 | 디자인·레이아웃·인터랙션 일관 |
| 4-3 | 3~5회 액션 안에 메뉴 접근 | 주요 기능 접근 간편, 불필요한 입력 없음 |
| 5-1 | API P95 Latency 3초 이내 | P95 3초 이내 **성능 테스트 결과** 제시 |
| 5-2 | HTTP Method별 기능 분리 | Method·URI 설계 명확 |
| 5-3 | 배포·운영 안정성 | 실제 배포 환경에서 오류 없이 동작 |
| 5-4 | 인증·인가 | JWT/OAuth 등 인증·인가 체계 |
| 5-5 | 비동기로 서버 응답 속도·자원 효율 | I/O 비동기 적용 + 개선 결과 제시 |
| 6-1 | 역할 분담 | R&R 문서화, 담당 업무 명확 |
| 6-2 | 협업 도구 | 버전·이슈·코드 리뷰·일정 관리 체계와 기록 |

- 같은 안내의 "2-3. 필수 구현 기능"(LLM 복약 가이드·챗봇·OCR)은 **진료기록 주제(3~5조)용**이라 여기 안 옮김
