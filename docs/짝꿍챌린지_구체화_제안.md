## 1. 검토 배경과 목적

- **[확정]** 11/17 멘토링: 짝꿍 챌린지를 1:1뿐 아니라 1:N으로 함께하는 방향 제안 → 제 담당으로 `pairs`·`challenges` 구조 재검토 지정
- **[확정]** 11/18 팀장님 요청: 짝꿍끼리 챌린지를 어떤 방식으로 진행할지 고민·조사 → DB 구조뿐 아니라 실제 운영 방식까지 검토
- **[확정]** wireframe S-14·S-17은 1:N 구조가 정해진 뒤 수정하기로 되어 있음
- **[확정]** 12/4 테스트 배포는 1:1 짝꿍 초대·수락·완료 여부 보기까지. 1:N은 확장 검토 과제이고, 6주 안에 구현할지는 아직 결정 전

이 글은 "1:N을 DB에 어떻게 넣을까"보다 먼저 **사람들이 계속 쓰고 싶은 협력형 챌린지를 어떻게 운영할지** 정하고, 그걸 현재 요구사항·ERD와 연결하려는 제안입니다.

## 2. 우리가 지향하는 경험

**건강관리는 누군가를 이기는 경쟁이 아니라, 서로 격려하며 조금씩 습관을 만드는 경험**이었으면 합니다. 이미 경쟁과 압박이 많은 일상에서, 짝꿍 챌린지만큼은

- 작은 실천도 인정받고
- 수치 대신 완료 여부만 나누며 서로 응원하고
- 못 한 날에도 부담 없이 다시 시작하는 공간이 되었으면 해요.

다만 취지만으로는 부족하고, **운영 방식이 그 취지에 맞게 설계되어야** 실제 참여와 습관으로 이어진다고 생각합니다.

이미 정해진 원칙과도 맞닿아 있어요.

- **[확정]** REQ-PAIR-003: 짝꿍에게는 완료 여부만, 건강 수치·위험도는 본인만
- **[확정]** REQ-NFR-007: 응원형 말투, 한 번 빠졌다고 반복해서 재촉하지 않음
- **[확정]** REQ-NFR-003: 실천 기록만으로 "위험도가 낮아졌어요"라고 말하지 않음 → 짝꿍 챌린지 문구에서도 동일하게 적용

## 3. 참고 사례와 적용 방식

### ① Duolingo Friends Quests

- **실제 기능**: 매주 친구와 짝지어 과제를 받고 정해진 기간 안에 함께 완료하는 주간 퀘스트. 각자의 진행이 전체 퀘스트 달성에 합산됨
- **참고할 원리**: 주 단위 공동 목표, 서로 다른 활동도 하나의 목표에 합산, 매주 새 미션
- **우리 적용**: 주간 공동 진행률 + "이번 주 함께 미션" 카드. **시스템이 무작위로 짝이나 미션을 배정하는 방식은 가져오지 않음** (우리는 아는 사람끼리 초대·수락, 미션은 사용자가 선택)

### ② Pokémon GO Party Play / Global Challenge

- **실제 기능**: 최대 4명이 파티를 이뤄 챌린지를 함께 수행. 호스트가 고른 챌린지에 모두가 기여하고, 완료하면 모두 보상을 받음. 진행 상황과 누가 가장 많이 기여했는지 확인 가능. 같은 과제라도 2인·3인 파티의 목표 수치가 다르게 설정됨
- Global Challenge: 전 세계 트레이너가 함께 하나의 과제를 달성하면 개인 진행과 관계없이 보상이 열림
- **참고할 원리**: 하나의 공동 게이지에 각자 실천이 쌓임, 인원수에 맞춰 목표 크기 조정, 개인 기여 표시
- **우리 적용**: 공동 진행률 = 참여자 개인 목표의 합, 기여는 순위가 아니라 "각자 채운 칸"으로 표시. 모르는 사람끼리의 대규모 협력은 장기 아이디어로만 보관

### ③ Strava

- **실제 기능**: 활동 피드에 kudos(좋아요)·댓글. Strava 디자인팀 인터뷰 연구에서 사용자들은 kudos와 댓글로 아끼는 사람을 인정·격려했고, 관계(클럽 동료, 가족 등)나 특별한 활동을 이유로 kudos를 줌
- **우리 적용**: 한 번 탭으로 보내는 가벼운 응원. 거리·속도 같은 성과 비교는 공유하지 않음

### ④ StepBet

- **실제 기능**: 참여자마다 과거 걸음 기록을 바탕으로 서로 다른 개인 목표가 정해짐. 한 주는 활동일 4일, 파워데이 2일, 휴식일 1일로 구성. 돈을 걸고 목표를 달성하면 다른 성공자와 상금을 나누는 구조
- **참고할 원리**: 같은 게임 안에서도 목표는 사람마다 다르게, 쉬는 날을 주간 구조에 처음부터 포함
- **우리 적용**: 같은 미션 + 각자 다른 주 N회 목표. "주 N회" 자체가 쉬는 날을 포함한 구조라는 점을 화면 문구로 살리기
- **가져오지 않을 것**: 돈을 거는 방식은 목표를 못 지키면 손해를 보는 구조라 "부담 없는 재시작"과 맞지 않고, 금전 처리도 범위 밖. 웨어러블 기반 자동 목표도 걸음 수가 직접 입력(11/17 결정)이라 이번엔 불가

## 4. 연구 근거

> **확인된 사실**과 **우리 해석**을 나눴습니다.

### ① Wing & Jeffery (1999)
*Benefits of recruiting participants with friends and increasing social support for weight loss and maintenance*, J Consult Clin Psychol

- 사실: 166명을 혼자 또는 친구·가족과 함께 모집. 혼자 + 표준 치료군은 76% 완료·24% 유지, 친구와 함께 + 사회적 지지 전략군은 95% 완료·66% 유지
- 한계: 참가자가 지인과 함께 등록할지를 스스로 선택했다는 점을 저자도 언급
- 해석: 짝꿍을 차별화 요소로 삼는 출발점. 체중 감량 연구이므로 "지속 참여" 측면의 참고로만 사용

### ② Lally 외 (2010)
*How are habits formed: Modelling habit formation in the real world*, Eur J Soc Psychol

- 사실: 96명이 12주간 매일 같은 맥락에서 행동을 실천. 습관이 자동화되기까지 18~254일로 편차가 컸고, 한 번 빠뜨린 것은 습관 형성 과정에 큰 영향을 주지 않았음
- 해석: **못 한 날을 실패로 다루지 않는 설계의 근거**

### ③ Harkin 외 (2016)
*Does Monitoring Goal Progress Promote Goal Attainment? A Meta-Analysis of the Experimental Evidence*, Psychol Bull

- 사실: 138개 연구(19,951명)에서 진행 모니터링을 늘리는 개입이 목표 달성을 높였음. 결과를 보고·공개하거나 기록으로 남길 때 효과가 더 컸음
- 한계: 공개 범주는 연구 수가 적어 불확실성이 크고, 왜 효과가 있는지는 증명하지 못함
- 해석: 완료 체크 + 완료 여부 공유 + 주간 달성률 구조의 근거

### ④ Patel 외 (2017) — BE FIT 시험
*Effect of a Game-Based Intervention Designed to Enhance Social Incentives to Increase Physical Activity Among Families*, JAMA Intern Med

- 사실: 94가족 200명(평균 55.4세)에게 협력·책임감·또래 지지를 높이도록 설계한 게임화 개입. 걸음 목표 달성 비율이 0.53 vs 0.32로 유의하게 높았고, 추적 기간에도 대조군보다 높게 유지
- 해석: 우리 타깃과 비슷한 중장년 **가족 단위** 협력의 근거

### ⑤ Patel 외 (2019) — STEP UP 시험 ⚠️ 우리 방향과 다른 결과도 공유
*Effectiveness of Behaviorally Designed Gamification Interventions With Social Incentives for Increasing Physical Activity Among Overweight and Obese Adults*, JAMA Intern Med

- 사실: 602명 대상. 지지·협력·경쟁 세 방식 모두 대조군보다 걸음 수가 늘었지만, 경쟁이 가장 효과적이었고 개입 종료 후에는 경쟁군만 유의하게 유지됨
- 해석: "협력이 경쟁보다 효과적"이라는 근거는 **없음**. 협력 중심은 30~60대 대상, 건강관리의 압박 최소화를 위한 **기획적 선택**. 경쟁을 원하는 사용자를 위한 선택형 비교 기능은 향후 후보로 남겨둠

## 5. 짝꿍 챌린지 운영 흐름 (핵심)

### 출발점: 설문 문항을 설계하며 정리한 사용자 니즈

기획 과정에서 사용자 입장의 설문 문항(어려운 습관, 참여 인원, 목표 정하는 방식, 공개 범위, 그만두게 되는 이유 등)을 직접 만들어 보며 아래 니즈를 정리했습니다.

- **모두에게 필요할 것**: 제시된 목록에서 고르기 / 매주 새로운 미션 / 완료 여부 + 주간 달성률 공유
- **사람마다 다를 것**: 참여 인원(1:1이 편한 사람, 상황 따라 바꾸고 싶은 사람) / 못 했을 때 원하는 반응(이전 성취 보여주기, 더 쉬운 목표, 기록 유지 후 재시작)
- **그만두게 될 이유**: 매일 기록하는 번거로움, 목표를 못 지키는 부담감
- **응원의 위치**: 응원은 있으면 좋지만 핵심 동기라기보다 보조에 가까움 → 중심은 공동 진행률·새 미션·쉬운 기록
- **추가 아이디어**: 물 컵 수·운동 시간처럼 간편하게 기록하기, 소액 포인트 보상

→ **모두에게 필요한 건 기본 흐름에, 사람마다 다른 건 고를 수 있게, 기록 부담은 설계로 줄이기**

### ① 시작: 고르기만 하면 되는 시작

1. 챌린지 탭 상단에 **이번 주 함께 미션** 카드, 아래에 기본 목록(걷기·물·운동·스트레칭·절주)
2. 템플릿을 고르면 주 N회가 기본값으로 채워져 있고 **−/+ 버튼으로만** 조절
3. 혼자 / 짝꿍과 선택 → 짝꿍 선택 → 상대가 수락하면 시작

- **[확정]** 기본 목록 + 주 N회 선택 (REQ-CHAL-001)
- **[제안]** 이번 주 미션 = 기존 템플릿 중 하나를 주차별로 돌아가며 강조. 시스템이 자동 배정하는 게 아니라 선택지 하나를 눈에 띄게 보여주는 것
- **[제안]** 목표 조정 제안은 AI 없이 규칙으로: 지난주 달성률 50% 미만이면 "다음 주는 한 번 줄여볼까요?", 2주 연속 100%면 "한 번 늘려볼까요?" (REQ-CHAL-004, 현재 낮음·검토 중)
- **[논의]** 건강 프로필 기반 맞춤 추천은 확정 기능이 아님. 한다면 위험 유형에 맞는 템플릿을 위에 정렬하는 정도부터, 그 이유(위험도)는 짝꿍에게 보이지 않게
- 제목을 직접 쓰는 완전 자유 목표는 비추천: 공동 진행률 계산이 어렵고, 목록에서 고르는 편이 사용자 부담도 적다고 판단

### ② 매일: 한 번 탭으로 끝

- **[확정]** 홈(S-12)에서 한 번 탭 = 완료 (REQ-CHAL-002)
- **[제안]** 어제 못 누른 체크는 다음 날까지 소급 가능 → 깜빡해서 끊기는 경험 방지. `checked_on`이 날짜 컬럼이라 API 규칙만 추가하면 됨
- **[향후]** 물 컵 수 같은 양 기록은 `challenge_checks`가 완료 여부만 저장해서 별도 설계 필요

### ③ 주간: 함께 채운 칸을 확인하는 리듬

- 월요일 시작, 일요일 마감
- **[확정]** 주간 리포트 알림(REQ-NOTI-007) → "이번 주 우리가 함께 채운 칸 10칸 중 8칸"
- 다음 주: 이어가기 / 목표 조정 / 이번 주 미션으로 바꾸기 중 선택

### ④ 못 했을 때: 재시작이 쉬운 화면

- "실패", "0일" 대신 **쌓아온 것 먼저**: "지금까지 함께 23번 실천했어요"
- 주가 남았으면: "이번 주 아직 2번 남았어요, 내일 한 번 해볼까요?"
- 2주 연속 낮으면 더 쉬운 목표 제안
- **[논의]** 연속 달성 표시(REQ-CHAL-003)와 알림(REQ-NOTI-006)은 확정 기능. 없애자는 게 아니라, 화면에서 **"이번 주 N회 / 누적 N회"를 "연속 N일"보다 먼저** 보여주자는 제안

## 6. 1:1과 1:N 운영, 공동 진행률·목표 설정

### 1:1 (기본, 12/4 범위)

- 지금 설계 그대로. 같은 템플릿을 둘이 함께, 서로의 완료 여부만 보고 응원 (REQ-PAIR-002·003)

### 1:N (확장, 12/4 이후 검토)

- **[제안]** 2~4명 (Party Play 상한 참고, 서로 챙길 수 있는 규모)
- **[제안]** 미션은 **같은 템플릿 1개**, 횟수는 **각자 정함**
  - 예: 동료 3명 "점심 후 10분 걷기" → 민수 주 3회, 지영 주 5회, 부장님 주 2회
  - 체력·일정이 달라도 같은 미션을 하며 부담은 각자에게 맞춤 (StepBet의 개인 목표 원리)
  - 서로 다른 템플릿을 섞는 건(물 + 걷기) 화면·계산이 복잡해 향후로
- 참여자끼리도 **완료 여부만** 공개. 참여 시 "이 챌린지 참여자에게 완료 여부가 보입니다" 안내

### 공동 진행률 [제안]: "함께 채운 칸 ÷ 전체 칸"

**개인 목표를 넘긴 체크는 칸에 더하지 않음**

위 예시의 한 주:

- 민수 3칸 중 3칸, 지영 5칸 중 2칸, 부장님 2칸 중 2칸
- (3+2+2) ÷ (3+5+2) = **10칸 중 7칸 (70%)**

이유:

- **이해하기 쉬움**: 퍼센트보다 "칸"이 직관적이고 1:1에도 똑같이 적용
- **공정함**: 목표가 큰 사람은 칸도 많아 기여가 자연스럽게 반영 (Pokémon GO가 인원수에 따라 목표를 키우는 원리)
- **압박 방지**: 한 사람이 몰아서 채울 수 없어 "내가 다 해야 하나" 부담이 없음. 넘긴 횟수는 개인 화면에 "보너스 +1"로만
- 대안인 "각자 달성률의 평균"은 위 예시에서 80%가 나와 직관과 어긋남

기여 표시는 순위·막대 비교 대신 **사람마다 채운 칸(●●○)** 만

### 응원·배지·알림

- **응원 [제안]**: 가벼운 보조 기능으로 두고, 프리셋 문구 한 번 탭 + 선택적 직접 입력, 같은 사람에게 하루 1번 정도로 제한. 화면 중심은 공동 진행률과 이번 주 미션
- **배지 [제안]**: 처음엔 저장 없이 계산해서 보여주는 2~3개만 (첫 공동 100% 주, 함께 4주 지속 등)
- **알림**: 멘토링 후 알림 종류는 늘리지 않기로 함 → 기존 짝꿍 알림(REQ-NOTI-005)을 쓰되, 1:N에서는 한 명 완료마다가 아니라 묶어서 보내기 [제안]

### 선호 차이 존중

- 1:1만 원하는 사람은 1:1만 써도 불편 없게. 1:N은 선택지
- 순위 비교를 원하는 사용자도 있을 수 있고 STEP UP도 경쟁 효과를 보여줌 → [향후] 다른 사람과의 순위 대신 "지난주의 나와 비교"부터 검토

## 7. 현재 ERD·요구사항 확인 결과

> 기준: develop 브랜치 `docs/erd.dbml`·`erd.md`·`requirements.md`·`wireframe.md` (11/18 커밋).
> 현재 코드(`app/models`)에는 `users`만 있고 챌린지·짝꿍은 구현 전이라, 아래는 설계 문서 기준입니다.

### 그대로 쓸 수 있는 부분

- `challenge_templates`: 기본 목록, 이번 주 미션도 여기서 선택
- `challenge_participants`: 참여자를 사람마다 한 줄씩, (챌린지, 사용자) 유니크 → **N명 저장 자체는 지금도 가능**
- `challenge_checks`: (챌린지, 사용자, 날짜) 유니크 → 1:N에서도 각자 하루 한 번, 공동 진행률 계산 가능
- `cheers`: 보낸 사람·받는 사람·챌린지 → 1:N에서도 개인 간 응원 가능

### 추가 설계가 필요한 부분 (모두 [제안], 미승인)

1. **1:N 챌린지와 `pairs` 연결**: `challenges.pair_id`는 두 사람 관계 하나만 가리킴
   - 안 A: 1:N은 `pair_id`를 비우고 참여자는 `challenge_participants`로만 관리, 초대 대상은 "만든 사람의 짝꿍"으로 API에서 제한 → **테이블 추가 없음**
   - 안 B: 그룹 테이블 신설 → 구조는 명확하지만 6주 범위에서 부담
   - 안 C: `pairs`에 있는 초대 코드 방식을 챌린지 단위로도 만들기 → 짝꿍이 아닌 사람도 참여 가능해져 공개 범위 논의가 커짐
   - 제 추천은 **안 A**
2. **개인별 목표 횟수**: `times_per_week`가 챌린지에 하나뿐 → `challenge_participants`에 개인 목표 컬럼 후보 (비어 있으면 챌린지 값 사용)
3. **참여 상태**: 1:N은 초대 후 수락·중간 나가기가 생김 → `challenge_participants`에 상태 컬럼 후보
4. **인원 상한·응원 제한**: 컬럼 없이 API 검사로 가능

### 문서끼리 확인이 필요한 차이

- "같은 두 사람 사이 짝꿍은 하나만"(11/17 결정)이 `erd.dbml`의 `pairs`에는 아직 제약으로 없음. A→B와 B→A 중복을 DB와 API 중 어디서 막을지 미정
- `challenge_participants`: `erd.md`는 `joined_at`, `erd.dbml`은 `created_at`
- `erd.md`의 "참여자 개인 1명, 짝꿍 2명" → 1:N 반영 시 문구 수정 필요
- REQ-PAIR-004(응원·공동 달성률·배지)는 중간·검토 중인데 wireframe S-17은 P1
- REQ-CHAL-004(목표 조정 제안)는 낮음·검토 중인데 wireframe S-15에 포함
- `requirements.md` 상단은 타깃 "불규칙한 생활패턴의 30~60대"로 11/17 확정, 하단에 "30~50대 vs 60대" 미결 항목이 남아 있음 → 상단 기준, 하단 정리 필요
- 미결: 짝꿍 해제 시 진행 중 챌린지 처리(종료 / 개인 챌린지로 계속). 1:N에서는 "한 명이 나가도 나머지는 계속"이 자연스러움

## 8. 구현 범위

**[확정] 12/4 테스트 배포**

- 템플릿 선택 + 주 N회, 오늘 완료 체크, 짝꿍 초대·수락, 1:1 짝꿍 챌린지, 짝꿍 완료 여부 보기

**[제안] 기존 구조로 비교적 간단히 가능**

- 1:1 공동 진행률(칸 방식), 프리셋 응원, 못 했을 때 문구, 이번 주 미션 카드, 규칙형 목표 조정 제안, 전날 소급 체크

**[제안] 추가 DB·API·화면 설계 필요**

- 1:N 초대·수락·나가기, 개인별 목표 횟수, 1:N 공동 진행률 화면, 알림 묶음, 배지 저장

**[향후 확장]**

- 맞춤 목표 추천(건강 프로필·LLM), 컵·시간 등 간편 수량 기록, 걸음 수 연동, 선택형 비교, 서로 다른 템플릿을 섞는 공동 목표, 모르는 사용자끼리 그룹 매칭, 포인트·현금성 보상(비용·운영 부담으로 보류)

## 9. 함께 정할 것

1. 1:N을 6주 안에 구현할지, 한다면 12/4 이후 언제까지
2. 1:N 구조: 안 A / B / C
3. 1:N 참여 자격: 만든 사람의 짝꿍만 vs 초대 코드
4. 공동 진행률 "칸" 방식 동의 여부
5. 화면에서 "이번 주 N회·누적"과 "연속 N일" 중 무엇을 먼저 보여줄지
6. S-17(공동 달성률·배지)과 REQ-PAIR-004 우선순위 맞추기
7. S-15 목표 조정 제안을 12/4 화면에서 뺄지, 규칙형으로 간단히 넣을지
8. 짝꿍 해제·1:N 중간 나가기 시 챌린지 처리
9. 같은 두 사람 짝꿍 중복 방지를 DB 제약으로 할지 API 검사로 할지
