# Pair2Care 가상 사용자 시나리오

> **은퇴 후, 우리 부부의 두 번째 건강한 일상** — *인생의 짝꿍이, 건강의 짝꿍이 되다.*  
> 만성질환 **진단 전 위험 단계**에 있는 가상 부부(아내 65세·남편 66세)를 설정한 아이디어입니다. 수치·상황은 가상이며, 아래 기능은 **팀에서 확정한 개발 요구사항이 아닌 제안**입니다.

## 1. 혈당 관리가 걱정되는 65세 아내

**① 누구인가?** 자녀가 독립한 뒤 남편과 지내는 65세 여성. 오전 6~7시 기상하며, 가족 식사를 챙기던 예전과 달리 혼자 먹을 때는 빵·떡·과일 등 간편한 음식으로 끼니를 해결하기 쉽다. 규칙적인 근력운동은 하지 않고, 남편과 함께할 새로운 활동을 찾고 있다.

**② 건강 상태** 최근 건강검진에서 **공복혈당 110mg/dL**(공복혈당장애 범위). 당뇨병 진단을 받은 것은 아니며, 탄수화물 위주의 식사와 단백질 섭취 부족 가능성을 걱정한다. 체력이 떨어진 듯 느끼지만 근육량 감소가 검사로 확인된 것은 아니다.

**③ 지금 불편한 점** 균형 잡힌 식사의 필요성은 알지만 매 끼니 메뉴·재료·양을 고민하기 번거롭고, 운동도 며칠 만에 중단한다. 식사·혈당·운동 기록이 흩어져 관리하기 어렵다.

**④ 기존 방법이 안 되는 이유** 건강검진 결과만으로는 내일 무엇을 먹고 어떻게 움직일지 정하기 어렵다. 식단 앱에 음식명·양을 매번 입력하기 번거롭고, 혼자 결심한 식습관 개선은 지속되기 어렵다.

**⑤ 언제 Pair2Care를 켜는가?** 아침에는 알림을 통해 추천 식단과 부부 챌린지를 확인하고, 식사 후에는 사진을 올린 뒤 AI가 잘못 인식하거나 누락한 음식명·재료·내용을 직접 고친다. 산책 전에는 날씨·약속에 맞춰 걷기/실내운동을 선택하고, 저녁에는 식단·운동·컨디션·공동 달성률을 확인한다.

**⑥ 가장 필요한 기능** **짝꿍 챌린지**(남편과 식사·산책 실천), **큰 글씨·버튼의 대시보드**, **LLM 식단·활동 추천**, **사진+직접 수정 가능한 식단 기록**, **선택적 혈당·체중·컨디션 기록 및 변화 그래프**.

## 2. 혈압과 활동량이 걱정되는 66세 남편

**① 누구인가?** 은퇴한 66세 남성. 오전 6~7시 기상하지만 출퇴근이 없어 활동량이 줄었다. 친구들과의 만남과 술자리가 일상의 즐거움이 되었고, 아내와 규칙적으로 함께하는 활동은 부족하다.

**② 건강 상태** 건강검진 혈압 **135/85mmHg**(고혈압 전단계 범위에 해당할 수 있는 가상 수치). 고혈압 확진 상태는 아니며, 단일 측정만으로 진단하지 않는다. 잦은 음주·짠 안주·운동 부족이 걱정된다.

**③ 지금 불편한 점** 술자리를 완전히 끊기보다는 횟수·양을 줄이고 싶지만 실천이 어렵다. 같은 걷기 코스는 지루하고 날씨가 나쁘면 쉬게 된다. 혈압 기록과 운동 성과도 한눈에 보기 어렵다.

**④ 기존 방법이 안 되는 이유** 검진에서 생활습관 개선을 권유받아도 구체적인 실천 계획이 없다. 은퇴 후 술자리가 중요한 낙이 되어 습관을 바꾸기 어렵고, 혼자 세운 절주·운동 목표는 오래 이어가기 힘들다. **배우자와 성취를 나누며 새로운 일상의 즐거움을 만들고 싶다.**

**⑤ 언제 Pair2Care를 켜는가?** 아침에 걷기·절주 목표를 보고, 측정한 날에는 수축기/이완기 혈압을 기록한다. 산책 전에는 날씨·계절·위치·약속에 맞는 장소와 **다른 이용자의 후기**를 확인하며, 악천후에는 실내 걷기·스트레칭으로 바꾼다. 부부 산책 후 선택적으로 사진 인증, 모임 전후 절주 기록, 저녁에는 달성률 확인과 배우자 응원을 한다.

**⑥ 가장 필요한 기능** **짝꿍 챌린지**(함께 걷기·건강한 식사), **걷기·절주·혈압을 한눈에 보는 대시보드**, **LLM 활동 추천**, **혈압·체중·컨디션 기록 및 변화 그래프**, **시간 설정 가능한 알림**.

## 3. 부부가 함께 이용하는 하루

- **아침:** 각자의 식단·운동·건강기록을 큰 버튼의 대시보드에서 확인하고, 공동 챌린지 목표를 정한다.
- **식사:** 식단 사진을 찍고 음식명·재료·식사 내용을 직접 입력하거나 AI 인식 결과를 수정한다.
- **산책 전:** 날씨, 개인 약속, 두 사람의 가능한 시간에 따라 공원·산책로(후기 참고) 또는 실내 활동을 고른다. 평소 오전 10시 산책과 진료 약속이 겹치면 **사용자 확인 후 오후 시간으로 변경을 제안**한다.
- **활동 후:** 각자 실천 완료를 체크하고 원하면 함께 찍은 사진으로 인증한다. 위치 공개·사진 등록은 선택한다.
- **저녁·주말:** 아내는 식사·혈당(측정 시), 남편은 혈압·절주를 확인하고 서로 응원한다. 일간·주간·월간 달성률과 배지를 보고, 동의한 경우에만 가족에게 성취를 공유한다.

**챌린지 예시:** 주 4일 함께 걷기(시간·강도 개인별 조절), 주 3회 건강 밥상 기록(단백질 식품·채소 챙기기), 날씨가 나쁘면 홈트레이닝·스트레칭으로 대체, 남편의 개인 절주 목표, 계절별 꽃길·공원·산책로 나들이 및 후기 작성. **벌칙보다 지속·성취·응원**을 중시하며, 아내는 남편의 음주를 감시하는 역할이 아니다.

## 4. 기능 아이디어 정리 (구현 확정 아님)

| 기능 | 제안 내용 및 고려사항 |
|---|---|
| **짝꿍 챌린지** | 부부 연결, 공동 목표 설정, 각자 실천 체크, 사진 인증(선택), 서로 응원, 일·주·월 달성률 및 성취 배지 |
| **고령자 친화 대시보드** | 큰 글씨·버튼으로 **식단 / 운동 / 건강기록 / 복약(해당자만)** 제공. 추천 식단, 걷기·실내운동·산책 장소, 개인 기록과 달성 현황을 직관적으로 확인 |
| **건강기록** | 실제 측정한 혈당, 혈압(수축기·이완기), 체중, 컨디션을 **선택 입력**하고 날짜별 변화 그래프 제공. 기록 그래프와 질환 발병 위험 예측은 별개 |
| **식단 기록** | 사진과 함께 음식명·재료·식사 내용을 입력하고 **AI 인식 결과를 직접 수정**. 사진만으로 음식 종류·양·영양소를 정확히 확정하지 않음 |
| **LLM 생활습관 추천** | 목표·선호·기록을 참고해 일반적인 식단, 걷기, 실내운동, 챌린지를 **이해하기 쉬운 문장**으로 제안. 검증된 건강정보를 바탕으로 하며 진단·치료를 대신하지 않음 |
| **알림** | 사용자가 기상·식사·운동 알림 시간을 정하고 켜고 끔. 웹 푸시는 브라우저·기기 지원 및 알림 권한 확인 필요 |
| **날씨·산책 추천 및 리뷰** | 비·폭염·한파 등에는 실내 걷기, 홈트레이닝, 스트레칭 영상 제안. 계절·위치·선호에 맞는 공원·산책로와 이용자 추천/비추천·짧은 후기 제공. 날씨·장소·영상 데이터 연동, 정보 최신성·접근성·이동 가능 여부·후기 관리는 검토 필요 |
| **일정 맞춤 챌린지** | 진료·모임·가족 약속과 활동이 겹치면 대체 시간/활동 제안, 부부 모두 가능한 시간 고려. 우선 서비스 내 일정 등록, 외부 캘린더 연동은 추후 검토. **승인 없이 일정 변경 금지**, 복약 시간 자동 변경 금지 |
| **복약 기록·알림(선택)** | 실제 처방약을 먹는 이용자만 **처방받은 약 이름·예정 시간**을 직접 등록. 알림을 누르거나 복약 화면에서 **실제로 먹은 후 '먹었음' 체크**. 미체크는 '미확인'이지 미복용 확정이 아님. 중복 복용이 의심되면 기록을 확인하고 약사·의료진에 문의하도록 안내. AI가 처방·용량·시간을 임의 변경하지 않음. 두 가상 인물이 약을 복용한다고 가정하지 않음 |
| **가족 연결·효도 리워드(선택)** | 부모 동의 시 성인 자녀 연결, 공유 상대·범위·빈도(일·주·월) 설정, 챌린지 달성 알림·하트/박수/응원 문구·가족 식사 메뉴 제안·자발적 선물 약속. **건강 수치 자동 공유 금지**, 전화 자체를 보상으로 취급하지 않음. 자녀가 없어도 핵심 기능 사용 가능. 실제 식당 추천은 정보 확보 후 검토하며 **송금·결제 기능은 제외** |
| **위험도 예측(별도 검토)** | 학습 데이터·예측 대상·검증 성능·의료적 안전성이 확보될 때만 검토하며 **이 시나리오의 필수 기능은 아님** |

**한 줄 요약:** Pair2Care는 은퇴한 부부가 각자의 건강 위험 요인을 관리하면서 서로의 **건강 짝꿍**이 되어 작은 생활습관 챌린지를 꾸준히 실천하고, 원한다면 가족의 응원까지 연결하는 서비스다.
