## 3. 현재 막힌 문제
1. **예측 데이터**: 국민건강영양조사 원시자료를 검토 중인데, 사용자가 앱에서 직접 답할 수 있는 설문 변수만으로 예측하면 변수가 적어 성능이 낮을까 걱정임. 고혈압·당뇨 각각 vs 대사증후군 하나로 할지도 아직 못 정함
2. **결과지 OCR**: CLOVA OCR로 검진 결과지에서 혈압·혈당을 읽고 사용자가 확인하는 방식을 생각했는데, 결과지 양식이 기관마다 달라 6주 안에 안정적으로 될지 판단이 어려움
3. **위험도 변화 표시**: 걷기 횟수 같은 실천 기록만으로 "위험이 줄었다"고 말하면 과장 같아서, 재설문으로 재계산한 값이 내려갔을 때만 보여주기로 함. 이게 사용자 동기 부여 면에서 약하지 않을지 고민임
4. **식단 이미지 클래스 수**: 타깃이 자주 먹는 음식(국밥·라면·김밥·떡볶이 등) 10개로 경량 CNN을 파인튜닝하고, 목록에 없거나 신뢰도가 낮으면 비전 LLM으로 보조하려 함. 10개면 실제 사용에서는 비전 LLM이 더 자주 쓰일 것 같아 클래스 수를 어느 정도로 잡을지 고민임

## 멘토링 결과 (11/17, 정현우 멘토)
> 멘토님 노션 메모 캡처 기준으로 정리함

### 서비스 방향: 경계에 있는 사람 → 습관 챌린지
1. **예측**: 고혈압·당뇨·대사증후군 3개 예측
   - 모델 코드는 AI가 잘 짜줌 → 핵심은 **"학습한 모델이 왜 좋은지 어떻게 증명하는지"**
   - MoE(mixture of experts)·앙상블 제안: 질환별 모델 3개 + 맨 앞단에 분류 모델
2. **짝꿍 챌린지**: 1대1뿐 아니라 1대N으로 챌린지를 같이 하는 것
3. **식단 사진 → 식생활 개선 → 다이어트**
   - 비전 LLM은 이미지 토큰 소모가 큼 → 줄이는 방법 고민, 흔들린 사진 보정
   - LLM으로 바로 보내지 말고 앞에 분류 모델(음료·식사·디저트)을 둘 수 있음
4. **운동 기록·대시보드·현재 건강 상태 시각화** (pair 구성원)
   - 데이터 집계 + 시각화는 AI가 압도적으로 잘함
   - 고혈압·당뇨 여부에 따라 다른 대시보드 구성: 무엇에 집중하고 주의할지, RAG

### 막힌 문제 답변
- **결과지 OCR**: CLOVA OCR(사진 속 모든 텍스트 + 좌표) → 정규식 후처리 → 가벼운 LLM으로 형식 맞춤. 파이프라인 설계가 관건
- **위험도 변화 표시**: 서비스 리텐션 UX 관점. 페어의 가치로 동기부여(서로 1시간마다 알림 등)
  - 알림은 PWA 웹 푸시로 됨
  - 앱은 사업자·등록비·심사가 필요하고, 오타 하나 수정에도 심사 → 비추천
  - 문자 알림은 생각보다 쉽고 빠르지만 비용 발생
  - 카카오톡 "나에게 보내기" 가능
- **식단 이미지 클래스 수**
  - 직접 라벨링은 1만~10만 장(크게는 100만~1000만 장) 규모가 필요 → **SOTA 음식 분류 모델을 찾아 파인튜닝**
  - 한식을 잘 판단하는지 확인, 출력은 자연어로 제한
  - 경량 CNN 또는 gpt-4o-mini급 모델, 결과는 영양소·칼로리 계산까지

### 멘토님 총평 (구두)
- **고민을 어떻게 녹여냈는지가 제일 중요함.** 구현 자체는 포트폴리오에서 가치가 없음
- 제로투원(0→1) 경험이 중요함 → **팀원 모두가 전체 플로우를 경험**하게 할 것
- AX 관점의 ROI: 무엇에 집중할지 정하기
- 아키텍처가 중요함 (모던 웹 아키텍처, 아키텍처와 인프라, 프로덕트 빌딩)
- 목업 데이터를 만들 때 과적합 주의, 특성 저장소(feature store) 언급
- 고혈압·당뇨·대사증후군은 **각각 따로 모델**을 만들 것
- 식단은 그냥 비전 모델도 방법 (예: 구글 Gemma)
- 알림을 강화해봤자 임팩트가 있을지 의문
